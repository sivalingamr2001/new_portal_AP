## Critical Issues Found

### 1. **SendStageEmailAsync is Defined but Never Called**
In your `AccessRequestService`, you defined `SendStageEmailAsync` and `BuildMailProgramSuffix`, but **they are never invoked anywhere** in the workflow methods (Submit, Resubmit, Renew, etc.). 

**You need to call this helper at each stage transition**, for example:

### 2. **Recipient Logic is Inverted in AccessRequestEmailNotificationService**
Look at this code:

```csharp
var requesterEmail = notification.Requester.Email?.Trim();
var toRecipients = !string.IsNullOrWhiteSpace(requesterEmail)
    ? new[] { requesterEmail }
    : new[] { recipientEmails[0] };  // Falls back to first HOD/IT person!

var ccRecipients = recipientEmails
    .Except(toRecipients, StringComparer.OrdinalIgnoreCase)
    .ToArray();
```

**Problem**: `notification.Recipients` contains HODs/IT operators (approvers), but you're sending **TO the requester** and **CC-ing the actual recipients** (approvers). 

For approval workflows, typically:
- **TO**: The person who needs to act (HOD/IT approver)
- **CC**: The requester (for visibility)

**Fix based on stage type:**
```csharp
// For approval requests (HOD/IT needs to act)
var toRecipients = recipientEmails; // HODs or IT operators
var ccRecipients = !string.IsNullOrWhiteSpace(requesterEmail) 
    ? new[] { requesterEmail } 
    : Array.Empty<string>();

// For status updates to requester (approved/rejected)
var toRecipients = !string.IsNullOrWhiteSpace(requesterEmail)
    ? new[] { requesterEmail }
    : recipientEmails;
var ccRecipients = Array.Empty<string>();
```
